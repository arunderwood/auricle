- **DR-1 (major, fix).** State writes carry no expected-state guard, and the trigger the story named for fixing that has fired.
  - `recordStageTransition` runs `UPDATE meetings SET state = ? WHERE id = ?` (`Sources/State/StateStore.swift:146`). The sweep reads candidates with `fetchPending()` and writes the stale failure later with no re-check (`Sources/Orchestrator/StageRunner.swift:187`, `:216`). A real Txn B that lands between the two is overwritten by a synthesized failure.
  - `updateMeeting(_:)` (`StateStore.swift:91-95`) is a public whole-row `meeting.update(db)` that includes `state`. Any writer holding an older `Meeting` snapshot reverts a transition made since. It bypasses the "single writer for `meetings.state`" discipline the epic's primitives list names.
  - Story 1.5 deferred this as "settled by … optimistic-concurrency guarding … before any real stage implementation starts calling `StageRunner.run` under true concurrent workloads" (`spec-1-5-…md`, first `deferred` entry). Epic 3's summarize worker is that caller (`App/auricle-cli/Verbs/InternalStageWorker.swift:89`). A late write can regress a finished, paid summarize.
  - Latent while nothing runs the sweep (SR-4), and live for any two workers on one meeting (DR-3).
- **DR-2 (major, accept, verified).** Story 1.8's lint rules shipped unable to match real code, and the self-check could not tell.
  - `4ff209a` (inside the Story 1.8 PR): `log_facade_bypass` "only matched the legacy `os_log(` free function", while `Log.swift` is built on `Logger(subsystem:category:)`. The rule "was never actually exercised against a real logging call shape".
  - `51eeeba` (after the merge): `atomic_writer_bypass` matched only the `write(to:)` spelling. `write(toFile:)` "went straight past" it. The commit message states the cause: the fixture carried one violation per rule, and the script only asserted that each rule id appeared somewhere, so a dead regex alternative stayed green.
  - The repair is in place. Each violation is marked `// expect: <rule id>` and the script asserts a hit on that line (the retro re-ran it: 13 marked lines fired). One alternative is still unmarked (VG-2).
  - Prevention, already adopted: assert per line and per alternative, not per rule id.
- **DR-3 (major, decide).** `CrashRecovery.reconcile()` re-dispatches without asking whether the old worker is still alive, and does not share a "stuck" test with the sweep.
  - It dispatches every `transcribing`, `reviewing_diarization` and `summarizing` meeting at launch, with no age check and no liveness or lease check (`Sources/Orchestrator/CrashRecovery.swift`, `reconcile`). The sweep applies a per-state age budget (`StageRunner.staleDetectionBudgetSeconds`). The two do not use one predicate.
  - The AC accepts re-running an idempotent stage (NFR-R5). It does not address two workers on the same meeting at once. A worker outlives its GUI, so a relaunch during a summarize can start a second paid call and race on the same cache artifact.
  - The `transcribing` budget is a fixed 60 s ("2× NFR-P3 (60s)", `StageRunner.swift`, doc comment on `staleDetectionBudgetSeconds`). NFR-P3 is defined for a 30-minute file (`epics.md:146`), so a longer file goes stale while healthy.
  - Nothing runs either mechanism today (SR-4). The decision is what "stuck" means, before Epic 6 wires them.
- **DR-4 (medium, fix).** An unexpected throw from `work()` records nothing. `StageRunner.run` propagates the error with no Txn B (`StageRunner.swift`, `run`). This is by design (`spec-1-5-…md`, "architecturally identical to a real subprocess crash"). The consequence is that a known failure waits for the stale budget (60 s to 720 s) and needs a sweep nothing runs. The summarize stage avoids this by returning `.failed` outcomes for the errors it expects, so the exposure is cancellation and unexpected errors. `CrashRecovery.reconcile()` keeps no attempt count (`CrashRecovery.swift`, `reconcile`), so a deterministic throw is re-dispatched on every launch, and each re-dispatch of a paid stage pays again (the `edge-case-hunter` lens's reading, consistent with the code).

- **DR-11 (minor, defer).** Timestamp precision is mixed. - **DR-13 (minor, fix, reproduced).** `ULIDFormat.isValid` accepts strings that are not ULIDs. It checks `string.utf8.count == 26` and then tests the *uppercased* characters (`Sources/Core/ULIDFormat.swift`, `isValid`). A character whose uppercase form is longer passes the byte-length test and expands into the alphabet. The retro compiled the same logic: 13 × `ß` (26 UTF-8 bytes) uppercases to 26 × `S` and is accepted. `MeetingID(ulid:)` then stores `SSSSSSSSSSSSSSSSSSSSSSSSSS` as the meeting's identity (`Sources/Core/MeetingID.swift`).
