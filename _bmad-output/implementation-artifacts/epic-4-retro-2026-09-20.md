## Findings

The diff-scope findings come from one read-only review pass over the cross-story seams. Findings 1 and 2 were re-checked by the retro against the source. Findings 3 to 6 are **reported** and rest on the review pass alone. Disposition key: **fix** = action item, **defer** = tracked, **accept** = recorded.

### F1. Diarization never reaches the published note (blocker, fix)

- **Spans:** 4.1/4.2 (transcribe, diarize) with 4.6/4.7/4.10 (attribute, run, exit test).
- **Evidence (verified):** `Sources/WhisperKitTranscriber/WhisperKitTranscriber.swift:23` labels every utterance `Speaker_1`, and `transcript.json` is immutable. `Sources/Summarize/SummaryArtifactMapper.swift:26` maps names by `speakers[utterance.speakerLabel]`. `renderTranscript` (`Sources/Attribute/AttributionRenderer.swift:48`) is defined but no code outside `Attribute` calls it. `utteranceIndex` is read only in the renderer and the reviewer prompt.
- **Effect:** `auricle run <id> --speakers "1=Ben,2=Sara"` attributes every utterance to one person and `needsAttribution` reads false. Part B would measure a pipeline that cannot distinguish speakers, which defeats the wedge thesis the epic exists to test.
- **Why tests passed:** `Tests/IntegrationTests/IntegrationStubs.swift:55` builds a transcript that is already labelled per speaker, so the join is never exercised.
- **Upstream cause:** no story owned the join from `diarization.json` and `attribution.json` to the labels Summarize reads. 4.2 produces, 4.6 renders, 4.7 wires, and none of the ACs says who consumes.

### F2. `--publish-anyway` note carries no `auricle/needs-attribution` tag (fix)

- **Evidence (verified):** `SummaryArtifactMapper.needsAttribution` (`:55-59`) only tests that each transcript label is a key of `speakers`. A publish-anyway file maps `Speaker_N` to itself, so it reads as attributed. `spec-4-6-*.md:13` records the intended fix. PR #87 states the same finding.
- **Overlaps with F1:** the fix needs the same label source.

### F3. `--from` and `--only` skip the state machine (fix, reported)

`Sources/Orchestrator/RunPlan.swift:173-176` rejects only terminal and permanent-failure states. `StageRunner.run` writes the `started` transition without `expectedState`. Example: `--only notify` on an `awaiting_attribution` meeting moves it to `awaiting_verification` with no note.

### F4. Re-transcribe leaves stale artifacts that attribute reuses (fix, reported)

`--force` and `--from transcribe` rewrite `diarization.json`. `Sources/Attribute/AttributionStage.swift:149-150` reuses the old speakers map, overrides and splits after checking only that the map is non-empty. A re-run of review overwrites `diarization_suggestions.json`, which the epic context says is written once.

### F5. `--publish-anyway` discards a saved attribution draft (defer, reported)

`AttributionStage.swift:131-133` ignores `inputs.existing`. The 4.6 and 4.7 specs say only "placeholders", so this is unspecified rather than wrong. It needs a product decision.

### F6. Smaller items (defer, reported)

- Interrupt handling builds failure metadata inline instead of using `StageRunner`'s builder (`PipelineRunner.swift:290-300`).
