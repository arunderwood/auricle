### Diff-scope review: the re-publish path

- **DR-1 (major, fix, verified by execution).** The re-run filename carries the capture date, not the re-run date. `PersistStage.publish` builds `localDate` from `captureStartedAt` (`Sources/Persist/PersistStage.swift:125`) and passes it to `nextRerunURL` (`:153`, `:234`). The plan requires the re-run date: `architecture.md:911-914` ("Re-run date is in the user's local timezone") and `:988` (a meeting from 2026-04-28 re-published on 2026-05-15 gets `--rerun-2026-05-15`). `epics.md:1279` says the same. A temporary test run on 2026-09-18 produced `2026-04-28-tuesday-sync--rerun-2026-04-28.md`. The tests pin the wrong value: `PersistStageTests.swift:169`, `:213`, `:246` all use `expectedLocalDate`, the capture date. All three lenses reported it independently.
- **DR-2 (major, fix, verified by execution).** A second re-publish nests the suffix. After a re-run, `PersistStage` repoints `meetings.vault_note_path` at the re-run file (`:136`). The next re-publish takes that file as `originalURL` and its stem (`:225`), so the candidate is `<stem>--rerun-D--rerun-D.md` (`:234`). The `-2` counter that `architecture.md:989` and `epics.md:1280` require is unreachable in the real flow. The temporary probe (two `isRepublish: true` runs) left `…-tuesday-sync--rerun-2026-04-28--rerun-2026-04-28.md`, and `vault_note_path` pointed at it. The test that claims to cover it (`PersistStageTests.swift:209-235`) seeds `vaultNotePath: originalURL.path` with the first re-run already on disk. That contradicts what the first re-run test asserts at `:206`, so it passes only through manual seeding. Reported, not measured: each re-run adds 18 characters, so a long slug can reach the 255-byte filename limit after about ten re-runs.
- **DR-3 (medium, decide, verified by reading).** Re-publish intent is a caller flag, and the retry paths lose it. `writeNote` takes the rerun branch only when `isRepublish` is true and the stored path exists (`:149-151`). Otherwise it goes to `VaultWriter.write`, whose collision loop sees the existing note and writes `<slug>-2.md` with no `supersedes` (`VaultWriter.swift:131-145`). Three triggers reach that: a bare `auricle run <id>` resume after a failed re-publish (Story 4.7 resumes `persist_failed`, `epics.md:2059`); a thrown `stateStore.updateMeeting` after a successful write (`PersistStage.swift:134-139`, caught at `:92-98`); and `isRepublish: false` against a meeting that already has a note. Story 2.4's recorded deferral names only the crash window (`spec-2-4-…md`, first `deferred` entry). No test runs `isRepublish: false` against an existing path (VG-1).
- **DR-4 (minor, decide, verified by reading).** The rerun branch ignores the configured vault location, and a moved note falls back silently. `vaultLocation` is not read on the rerun branch (`:148-159`), and `VaultWriter.writeExact` skips vault validation (`VaultWriter.swift:57-59`). A `vault_path` or `meetings_subdir` change after the first publish sends re-runs to the old folder. A note the user renamed or moved in Obsidian fails `fileExists` (`:151`), so the stage writes a fresh note with `supersedes: nil`, the same fallback the plan reserves for a deleted original (`architecture.md:910`).

### Diff-scope review: other

- **DR-5 (medium, decide, verified by reading).** Local date and time use the time zone at persist time, not capture time. `localDateAndTime` sets `calendar.timeZone = .current` (`PersistStage.swift:253-260`). `MeetingForFilename.swift:9-11` says "local time at capture", and `epics.md:1189` says "local timezone at capture time". No column stores a capture-time zone (search of `Sources/State` and `Sources/Core` found none). A capture before travel, or a retried persist in another zone, can shift the note date by a day. Two lenses reported it. The summarizer's `"Meeting at … <zone>"` title can then disagree with the filename.
- **DR-6 (medium, closed, verified).** The renderer prefixed only the first line of a multi-line quote with `> `. Story 2.1's fixtures used single-line quotes. Epic 3's cross-stage test exposed it, and `ada47d8` fixed it (`FrontmatterRenderer.swift:105-116`, `deferred-work.md:70`, closed at `:139`). A sibling defect is still open: item `text` with a line break splits the bullet (`FrontmatterRenderer.swift:100`, `deferred-work.md:106`).
- **DR-7 (minor, fix, verified by comparison with libyaml).** Emoji in a title are written as `\U0001F389` escapes. Story 2.1's spec records that libyaml cannot emit code points above U+FFFF (`spec-2-1-…md:258`) and set `followup_review_recommended: true`, which nothing closed. A PyYAML `CDumper` run on this machine (libyaml, `allow_unicode=True`) produced `"\U0001F389 Launch é 北京"`. Yams bundles libyaml but was not run directly. YAML readers decode the escape, so Obsidian's Properties view still shows the emoji. The raw file does not. No test covers a supplementary-plane title.
- **DR-8 (minor, defer, verified by reading).** `PersistStage.publish` fetches the whole `Meeting` row (`:113`) and writes it back with `updateMeeting` (`:137`, `StateStore.swift:91-95` runs `meeting.update(db)`), with a vault write in between. The Epic 1 retro's action item `epic-1-retro-item-11-guard-state-writes-with-an-expected-stat` already replaces `updateMeeting` with column-scoped writers, which covers this call site. ### Architecture delta

- **AD-1 (medium, decide, verified by reading).** Persist runs under `.summarizing`, and two other components map that state to the summarize stage. `ActiveStageInFlight.stage(for: .summarizing)` returns `.summarize` (`Sources/Orchestrator/ActiveStageInFlight.swift:13-18`). `CrashRecovery` re-dispatches that stage for any meeting found in `.summarizing` (`CrashRecovery.swift:24`, `:68-77`). A persist crash therefore re-runs a paid summarize subprocess. The stale sweep marks a stuck persist as `summarization_failed` (`StageRunner.swift:138-139`, 720 s budget). Story 2.4 recorded a milder reading: "misattribute a hung persist as a hung summarize" (`spec-2-4-…md`, second `deferred` entry, severity medium). Epic 3 recorded the reverse case: a finished summarize waiting for persist can be swept to `summarization_failed` (`deferred-work.md:82-83`). One design gap sits behind both entries. The fix needs a `persisting` state or a way for the sweep and crash recovery to tell the stages apart.
- **AD-2 (minor, defer, verified by reading).** The schema version is written three ways: `PersistStage.frontmatterSchemaVersion` (`PersistStage.swift:15`), the renderer's caller-supplied `schemaVersion` (`MeetingForFrontmatter.swift:13`), and the reader's two bounds (`FrontmatterReader.swift:45-46`). A writer bump without a reader bump would make the app's own reader reject its own notes as too new. One shared constant, or a test that reads back a note rendered with `PersistStage`'s version, would prevent it.
- Checked and clean: `Persist` depends on `Core`, `State`, `Telemetry`, `Orchestrator` and Yams (`Package.swift:90-93`). No cycle. The retro did not compare `Package.swift` with the graph in `architecture.md` for this epic.
- Checked and clean: no file passes 400 lines. `PersistStage.swift` is the largest at 304. There is no god-class.

### Pattern divergence

- Persist has no `Log` call (search of `Sources/Persist` found none), although `architecture` lists `persist` as a logging category (AR-PAT-3, `epics.md:308`). A failed publish shows up only as a `stage_events` row. Recorded, not routed: no story required a log line.

### Process lessons

- **PL-1 (major, prevention).** Literal example tables in the plan were not turned into tests. `architecture.md:988-989` gives the exact re-run filenames, and the code got both wrong (DR-1, DR-2). Story 2.4 closed with `review_loop_iteration: 0`. Its review found the crash window and the state mapping, and did not chain two runs. Prevention: an AC that carries an example table gets one test per row through the public entry point. A path whose input depends on an earlier run's output gets a test that runs it twice.
- **PL-2 (medium, prevention).** Four of five specs carry `warnings: oversized` (2.1 to 2.4). Story 2.2 took four review passes and three `bad_spec` amendments for one algorithm, the attendee slug. The ambiguity came from the plan text ("≤3 attendees"), and the corrected rule stayed in the story spec (SR-4). Prevention: when review corrects the meaning of plan text, reconcile the plan text in the same story.
- **PL-3 (medium, prevention).** `deferred-work.md` holds none of the seven `deferred` entries in the Epic 2 specs. A search of the ledger for `spec-2-`, `TOCTOU`, `needs-summary` and the emoji finding returns nothing. Story 2.1 also ends with `followup_review_recommended: true` and no closure (DR-7). Epic 3's PL-3 found the same drift for its own stories.
- **PL-4 (minor, accept).** Epic 1's enforcement layer had defects that Epic 2 work exposed. The `atomic_writer_bypass` regex missed `write(toFile:)` (`51eeeba`). `log_facade_bypass` never matched the API `Log.swift` uses (`4ff209a`). The pre-commit hook crashed under `git commit`, and Story 2.1's commit used `--no-verify` once with the maintainer's authorization (`spec-2-1-…md:266`; fixed in `755adcc` and `14d5299`). All were fixed inside the epic window, so this is closed.
- **PL-5 (minor, prevention).** Epic 2 had no retrospective before Epic 3 started, and Epic 3's retro did not examine `Sources/Persist` beyond the lines it cites. DR-1 to DR-3 lie on the path Story 4.7's `--reattribute` will use.
- Not analyzed: session logs. Why a session took an unexpected turn is unknown except where a spec's review record says.
