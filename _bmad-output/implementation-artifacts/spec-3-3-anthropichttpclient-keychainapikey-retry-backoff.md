## Intent

**Problem:** `Sources/ClaudeSummarizer/` is still `ManifestPlaceholder.swift`. Every future Anthropic caller (`ClaudeCitationsSummarizer`, `ClaudeSubstringSummarizer`, and eventually `ClaudeAIReviewers`) needs one shared HTTP layer with consistent retry/backoff, TLS, secret-handling, and log-redaction semantics per NFR-R9/NFR-S1/NFR-S5/NFR-S7 — none of that exists yet.

**Approach:** Add `AnthropicHTTPClient` (wraps `URLSession`, exponential backoff, typed-error mapping, redacted logging) and `KeychainAPIKey` (Keychain-backed secret read/write) to `Sources/ClaudeSummarizer/`. Both are generic infrastructure: this story does not build Anthropic wire-format request bodies (citations/substring shapes) or the orchestrator — only the transport layer those later stories call.

## Boundaries & Constraints

**Always:**
- `AnthropicHTTPClient` is an instance (struct/class, not `actor` — no mutable state is shared across concurrent `send()` calls, unlike `SummarizerOrchestrator`) with `send(_ request: AnthropicRequest) async throws -> AnthropicResponse`. `AnthropicRequest`/`AnthropicResponse` are body-shape-agnostic: the caller supplies the raw JSON body + any extra headers; the client parses only the standard envelope (`model`, `usage.input_tokens`/`output_tokens`/`cache_creation_input_tokens`/`cache_read_input_tokens`, `stop_reason`) and passes `content` through opaquely. Building the Citations/substring request shape is Story 3.4/3.5's job.
- The API key is read via `KeychainAPIKey.read()` once per `send()` call (covering all its retries, not once per retry) and never stored as an instance property. The read source is an injectable closure (default `{ try KeychainAPIKey.read() }`) so this client's own tests don't depend on a real Keychain item.
- `URLSessionConfiguration.tlsMinimumSupportedProtocolVersion` is explicitly set to `.TLSv12` (NFR-S5) — don't rely only on the OS default.
- Retry/backoff: 429 or any 5xx or a network-level timeout escalates `1s → 2s → 4s → 8s → 16s`, then holds at 16s for further retries, until cumulative elapsed retry time reaches a total budget (default 300s per NFR-R9). The schedule, sleep primitive, and budget are constructor-injected with production defaults (same pattern as `Sources/Orchestrator/RetentionScheduler.swift`'s `interval`/`now` injection) so tests exercise real retry logic without waiting in real time.
- HTTP-status → outcome mapping (Anthropic's documented error taxonomy): `401`/`403` → no retry, throw `SummarizerError.authenticationFailed` immediately. `402` → no retry, throw `.quotaExceeded` immediately. `429`/any `5xx` → retry per the schedule above; on budget exhaustion throw `.rateLimited`. A network-level failure with no HTTP response (timeout, connection failure) → retry the same way; on budget exhaustion throw `.networkTimeout`. Any other non-2xx status (`400`, `404`, `413`, etc.) → no retry, throw `.malformedResponse`. `.citationsUnavailable` and `.featureToggleDisabled` are never thrown from this client — they're strategy-level (Story 3.4/3.5) concerns.
- Cancellation propagates uncaught by the retry loop: `Task.sleep(for:)` throws `CancellationError` on cancellation, and `URLSession`'s async `data(for:)` throws `URLError(.cancelled)` when its task is cancelled — the retry loop's catch clause must not treat either as a retryable network failure.
- Only redacted metadata is ever passed to `Log` (`Sources/Core/Log.swift`): status code, input/output/thinking token counts, `costUSD`, model identifier — as `.publicSafe` fields. The response body/content is never passed to `Log` in any field, `.sensitive` or otherwise (stronger than `Log`'s own redaction, which is proven separately in `Tests/CoreTests/LogRedactionTests.swift`). Structure the code so the fields passed to `Log` are built by a small, pure, internally-testable function — mirroring how `Log.buildMessage` itself is unit-tested directly — so this guarantee is verifiable without capturing real OS log output.
- `costUSD` is computed from the response's `usage` token counts via a small static per-model rate table in this target (e.g. `claude-opus-5`, `claude-haiku-4-5`, at their published per-MTok input/output rates), not a config file — no config-loading component exists yet in this codebase (confirmed: no `Config`/TOML-reading type anywhere under `Sources/Core`) and building one is out of scope here. An unrecognized model identifier falls back to the `claude-opus-5` rate. `thinkingTokens` is reported as `0` unless the response's `usage` object carries a distinct thinking-token count — the Messages API currently bundles thinking tokens into `output_tokens`, so don't fabricate a derived estimate.
- `KeychainAPIKey` is an enum namespace with `static func read() throws -> String` and `static func write(_ key: String) throws`, matching the AC's own call syntax verbatim. Stored as `kSecClassGenericPassword` under the stable service identifier `com.auricle.app.anthropic-api-key`. `write(_:)` upserts (update-in-place if an item already exists, add otherwise) — rotating the key must not require a manual delete first. A missing key on `read()` throws `KeychainError.notFound`.
- `KeychainAPIKeyTests` use a distinct test-only service identifier (never the production `com.auricle.app.anthropic-api-key`) and each test deletes what it wrote within the same run — tests must never depend on or mutate the maintainer's real stored key.

**Never:**
- Don't build `AnthropicRequest`'s citations-vs-substring content-block wire format, `cache_control` JSON, or any prompt/glossary text — Story 3.4/3.5's scope (per Decision 3.2/3.4).
- Don't build `SummarizerOrchestrator` or fallback-dispatch logic — Story 3.6's scope (Decision 3.3).
- Don't wire SIGINT-to-`Task.cancel()`-to-exit-130 — that's the CLI/`auricle run` entry point's job (Story 3.7 + Orchestrator); this story only ensures cancellation isn't swallowed.
- Don't add a `Package.swift` dependency edge from `ClaudeAIReviewers` to `ClaudeSummarizer` — out of scope; the future `ClaudeDiarizationReviewer` story wires that when it actually calls `AnthropicHTTPClient`.
- Don't wrap `URLSession` or Keychain access in a new protocol abstraction (architecture.md's explicit constraint: "do not wrap `URLSession`, `Keychain`... in protocols unless there are actually two implementations or a real testing need") — use concrete-type/closure injection instead, per the boundaries above.
- Don't build a config-file-backed rate table or touch `~/.auricle/` — the hard-coded rate table above is an explicit, documented stand-in until a real config story lands.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Successful request | Stub returns 200 + valid envelope | `send()` returns decoded `AnthropicResponse` with usage/cost/model populated | No error |
| Transient rate limit | Stub returns 429 twice, then 200 | Retries with 1s→2s backoff, then succeeds | No error |
| Persistent 5xx | Stub always returns 500 | Retries per schedule until budget exhausted | throws `SummarizerError.rateLimited` |
| Persistent network timeout | Stub simulates request timeout every attempt | Retries per schedule until budget exhausted | throws `SummarizerError.networkTimeout` |
| Auth failure | Stub returns 401 | No retry, immediate throw | `SummarizerError.authenticationFailed` |
| Billing failure | Stub returns 402 | No retry, immediate throw | `SummarizerError.quotaExceeded` |
| Malformed/other 4xx | Stub returns 400 | No retry, immediate throw | `SummarizerError.malformedResponse` |
| Cancellation mid-retry | Task cancelled during a backoff sleep after a 429 | In-flight sleep/request aborts immediately | `CancellationError` (or `URLError(.cancelled)`) propagates, not caught/retried |
| Redaction | Stub response body contains a distinctive marker string | Marker never appears in any field passed to `Log` | No error |
| Keychain round-trip | `write("sk-ant-test")` then `read()` | Returns `"sk-ant-test"` | No error |
| Keychain missing | `read()` with no item under the test service id | — | throws `KeychainError.notFound` |

**Acceptance Criteria:**
- Given a stubbed 200 response, when `send()` runs, then it returns a decoded `AnthropicResponse` with no retry and no error.
- Given a stubbed 429 followed by a 200, when `send()` runs, then it retries with the documented backoff and returns the eventual success.
- Given a stub that always returns 500 (or always times out), when `send()` runs past the injected total budget, then it throws `SummarizerError.rateLimited` (`.networkTimeout` for the timeout case) and never exceeds the budget.
- Given a stubbed 401 or 402, when `send()` runs, then it throws `.authenticationFailed`/`.quotaExceeded` immediately with zero retries.
- Given a `Task` cancelled during a backoff sleep, when `send()` is awaited, then cancellation propagates and no further retry attempt is made.
- Given any response, when `send()` logs anything, then no field passed to `Log` contains the response body, under any sensitivity tag.
- Given `KeychainAPIKey.write("x")` then `.read()` under the test service id, then `.read()` returns `"x"`; given no item exists, then `.read()` throws `KeychainError.notFound`.

## Design Notes

**Why an instance method, not a static call, despite the AC's `AnthropicHTTPClient.send(...)` phrasing:** the retry schedule, session, and API-key source all need per-instance test overrides (mirroring `RetentionScheduler`'s constructor injection); a static function couldn't accept those without polluting every call site. The AC's syntax is illustrative of the type+method name, not a mandate for a static call — same reading Story 3.1 gave `SummarizerStrategy.summarize(...)`.

**Why the backoff schedule plateaus at 16s instead of continuing to double:** the AC gives a closed 5-step sequence (`1→2→4→8→16`) plus a separate 5-minute *total* budget that is over 9x the sum of that sequence (31s) — the only reading that uses both numbers meaningfully is escalate-then-hold-at-the-cap-until-budget-exhausted, the standard shape for "exponential backoff with a total time budget" (matches Decision 4.2's own "cap, not floor" framing of the budget, not the per-step delay).
